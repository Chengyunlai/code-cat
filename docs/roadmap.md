# 路线图

本文件写**可证伪的假设**，不是功能清单。每条给出编号、假设、验证方式与通过标准；没有通过标准的条目不应该被排期。

已完成阶段的实际结果不在这里，见 [`implementation/`](implementation/) 各阶段记录与 [CHANGELOG.md](../CHANGELOG.md)。本文件不承诺时间。

## 待验证假设

### H1 · JetBrains 端接入变量与完整调用栈

- **假设**：JetBrains 平台 API 能在真实暂停时提供与 VS Code 同等粒度的变量与栈帧，共享 UI 无需分叉。
- **验证方式**：在 WebStorm 2025.1 的 TS source-map 断点上采集变量与完整栈帧，用现有证据规范化规则（去重、折叠换行、限制长度、遮盖敏感字段）处理，并在 JCEF 页面回读断言。
- **通过标准**：隔离宿主测试中，JCEF 页面能读到真实变量名与值、栈帧数量与顺序，且与 VS Code 端渲染同构。

### H2 · PyCharm 2026.1 的 Python 真断点

- **假设**：PyCharm 免费版缺少 NodeJS 调试器不影响 Python 调试链路，`examples/python-order-service` 能在 PyCharm 中停在教学断点。
- **验证方式**：在 PyCharm 2026.1 装本地 261 包，用 `examples/python-order-service` 走一次引导调试。
- **通过标准**：真实停在预期源码行，暂停位置与附近源码正确呈现；若失败，记录失败环节并把它写进阶段记录，而不是继续沿用 WebStorm 的结论。

### H3 · 用符号与调用层级检索替代单次路径规划

- **假设**：当前路径规划只做一次模型请求，先做确定性的符号与调用层级检索、再做一次更小的证据约束模型调用，能得到更可靠的路径且不增加成本。
- **验证方式**：为同一批问题（含中文提问）对比两种实现的路径命中率与模型 Token 用量。
- **通过标准**：路径中「模型给出的站点」被人工判定为高价值位置的比例上升，且单次提问的 Token 用量不高于现状。

### H4 · 多根工作区路径消歧

- **假设**：多根工作区下，路径与检索结果可以按「提问所属的根」消歧，不会把另一个根的文件当成候选。
- **验证方式**：构造双根工作区，两侧放置同名文件与同名符号，断言检索与源码跳转都落在正确的根。
- **通过标准**：断言稳定通过，且越界路径被拒绝并给出明确提示。

### H5 · 收敛宽泛符号回退

- **假设**：在保留中文提问命中的前提下，可以缩小当前 600 符号的宽泛回退，从而降低提示词体积。
- **验证方式**：对一组不含英文标识符的中文问题，比较收敛前后的检索命中与 Token 用量。
- **通过标准**：中文问题的命中不回退，提示词 Token 明显下降。

### H6 · 结构索引升级为真正的解析器

- **假设**：当前基于声明扫描的索引在嵌套类、条件定义、装饰器等场景会漏，换成解析器能修正这些漏检。
- **验证方式**：构造上述场景的样例仓库，比较两种索引产出的符号表。
- **通过标准**：样例中的符号全部进入索引，且索引构建耗时可接受。

### H7 · 会话历史云同步

- **假设**：用户愿意让阅读会话跨设备同步，且这不与「不向项目目录写文件」的约束冲突。
- **验证方式**：先做只读调研（询问用户是否需要、可接受的存储位置），再决定是否实现。
- **通过标准**：需求被明确确认后才进入实现；没有确认就不做。

### H8 · VS Code Marketplace 发布

- **假设**：仓库已具备发布所需的元数据与验证，可以打包上架。
- **验证方式**：补齐发布元数据，用 `vsce ls` 核对包内容不含贡献者文档与构建产物，再走一次完整冒烟。
- **通过标准**：包内容符合预期、冒烟全绿，且用户明确授权发布。

### H9 · 逐一验证其他 JetBrains 产品

- **假设**：除 WebStorm 2025.1 与 PyCharm 2026.1 之外，其他 JetBrains IDE 也能加载本插件。
- **验证方式**：对每个产品单独构建并用 Plugin Verifier 检查，再至少验证一次加载。
- **通过标准**：每个被声明的产品都有独立证据；没有证据的产品不写进 README 与插件描述。

### H10 · CI 扩展到构建与测试

- **假设**：当前只校验文档链接的 CI 可以扩展到类型检查与引擎测试，并在 CI 环境稳定通过。
- **验证方式**：在 CI 中依次加入 `npm run check` 与 `npm run test:engine`，观察连续多次运行是否稳定。
- **通过标准**：连续多次运行不出现偶发失败；需要图形环境或真实 IDE 的测试（Webview 渲染、两个宿主冒烟）仍留在本地。
