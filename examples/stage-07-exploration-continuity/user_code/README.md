# 同一个目标下问三次

运行：

```bash
node examples/stage-07-exploration-continuity/user_code/main.cjs
```

输出（节选）：

```text
提问：结账时库存是怎么预留的？

第一次提问之后
  探索目标：结账如何预留库存
  路径共 2 站：
  1. checkout.py:2 结账入口
  2. inventory.py:3 库存预留

提问：那库存不足时会走到哪一行？

第二次提问之后（同一目标，路径变长）
  探索目标：结账如何预留库存
  路径共 3 站：
  1. checkout.py:2 结账入口
  2. inventory.py:3 库存预留
  3. checkout.py:4 库存不足的分支 [新增 · 来自「那库存不足时会走到哪一行？」]

  第二次提问的提示词带上了当前目标：true
  第二次提问的提示词列出了已有站点：true
  第二次提问的提示词要求只返回新增：true

提问：那支付扣款是在哪里发生的？

第三次提问之后（换了目标，但还没确认）
  探索目标：结账如何预留库存
  待确认的新目标：支付扣款如何发生
  路径共 4 站
  ...

用户选择「开始新的探索目标」：true

确认新目标之后
  探索目标：支付扣款如何发生
  路径共 1 站：
  1. payment.py:2 扣款调用 [新增 · 来自「那支付扣款是在哪里发生的？」]
```

使用者只做两件事：连问三个问题，然后看路径。`SessionStore` 与 `AiTutor` 都是公开入口，宿主用的就是它们。

三处值得对照着看：

1. **第二次提问之后路径变成 3 站而不是 2 站。** 固定回答里故意把 `inventory.py:3` 又给了一遍，它没有出现在第 3 位——同一「文件 + 行」不重复追加。这正是加入本阶段之前做不到的：那时每次提问都整条替换路径，上一条链路连同已经采集到的现场证据一起消失。
2. **第二次和第三次提问的探索目标都没有被改写。** 固定回答第二次不带 `goal`，于是沿用第一次的目标；第三次带了 `goalChanged: true`，目标仍然不动，只把新目标放进「待确认」。确认之前，旧站点原样保留。
3. **提示词里带上了当前目标与已有站点。** 示例直接断言了提示词里的三句关键指令，因为「路径为什么不会漂移」这件事发生在提示词里，不在渲染里。

示例里固定回答是手写的，真实链路里由模型生成（`AiTutor.answerQuestion`）。写死是为了不依赖模型也能复现这条路径。
